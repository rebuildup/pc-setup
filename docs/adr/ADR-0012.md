# ADR-0012: macOS keyboard baseline は hidutil と user LaunchAgent で管理する

- Status: Accepted
- Date: 2026-10-06
- Supersedes in part: ADR-0005

## Context

実機Macが導入され、共通CLI bootstrapとGUI導入を実行できる状態になった。キーボードはWindowsと同様に、単純で安定した低レイヤー変換と、将来のkanataによる高度なカスタマイズを分離したい。

大西配列の文字位置は1:1のHID usage置換で表現でき、macOS標準の `hidutil` がこの責務を満たす。`hidutil` のUserKeyMappingは再起動やkeyboard service lifecycleを越えて永続化されないため、desired stateとして再適用する仕組みが必要になる。

## Decision

### Base layout ownership

大西配列の単純な1:1置換は `hidutil` が所有する。

repositoryは `platforms/macos/keyboard/onishi.json` をcanonical mappingとする。

実機で確認した重要なmappingを含む。

- physical `G` -> `-`
- physical `-` -> `/`
- physical `/` -> `B`

physical backtickからslashへのmappingは採用しない。

### Startup convergence

user sessionの入力設定なので、`~/Library/LaunchAgents` のLaunchAgentからログイン時に再適用する。

bootstrapはuser-local helperとLaunchAgent plistをidempotentに配置し、その場でもmappingを適用する。system-wide LaunchDaemonやroot常駐processは使用しない。

### Layer boundary

`hidutil` はbase layoutの1:1変換だけを所有する。

tap-hold、layer、chord、navigation、shortcut等のstateful behaviorは将来のkanata layerで扱う。Karabiner-Elementsを同じ物理keyboard grab layerとして常駐させることはこのdecisionに含めない。

### macOS platform state

実機Macが存在し、実際のbootstrapとkeyboard desired stateを観測できるため、macOS固有のcanonical directoryを `platforms/macos` に開始する。

未確定のGUI/creative/audio候補は引き続き `plans/macos` に残し、実使用を確認したものから段階的にActive stateへ移す。

## Verification

repository CIはcanonical JSONの構文とcritical mapping pair、LaunchAgent plist構文、shell syntaxを静的に検証する。

実機verifyはinstalled helper/plist、launchd registration、`hidutil` availabilityを確認する。Privacy permissionやkanata driverはこのADRの対象外。

## Consequences

- fresh/rebuilt Macでも大西配列baselineを再現できる
- layoutと高度なkeyboard behaviorの責務が分離される
- mappingはuser login後に収束するため、FileVault pre-boot/login screen等のuser session外では対象外
- external keyboardのservice reset等でmappingが消えるケースは必要性を観測してから追加対策する
