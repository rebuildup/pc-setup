# ADR-0007: Open Code Review Uses Verified GitHub Release Binaries

- Status: Accepted
- Date: 2026-09-23
- Extends: ADR-0006
- Superseded by: None

## Context

Open Code Review is part of the portable CLI baseline managed by `mise.global.toml`.

It was initially declared through mise's npm backend as `npm:@alibaba-group/open-code-review@latest`. During an Ubuntu/WSL bootstrap, mise 2026.9.12 rejected the selected npm release because its supply-chain evidence represented a trust downgrade: an earlier published package had npm provenance attestation while the selected release did not.

The failure was therefore a security gate working as intended, not an ordinary dependency-resolution failure.

Possible bypasses included:

- globally delegating npm installs to the npm CLI
- adding a package-wide trust-policy exclusion
- adding a version-specific trust-policy exclusion

All three weaken or bypass the failing verification boundary. The first two also affect a broader scope than Open Code Review.

Open Code Review publishes official per-platform binaries on `alibaba/open-code-review` GitHub Releases for Linux, macOS and Windows, together with SHA-256 checksum material. Its official installer also consumes these release assets.

## Decision

Open Code Review MUST be installed through mise's `github:alibaba/open-code-review` backend rather than the npm backend.

The global mise configuration:

- tracks the latest stable GitHub Release
- maps the upstream Linux/macOS/Windows asset names explicitly
- exposes the downloaded binary as `ocr`
- keeps mise's GitHub release verification path enabled
- does not add an npm trust-policy exclusion for Open Code Review
- does not enable `npm.shell_out=true` as a workaround

The repository CI performs one real Open Code Review installation on Linux in addition to the normal mise dry-run. This specifically validates the download/asset-selection path that failed on the observed WSL bootstrap.

## Consequences

### Positive

- the bootstrap no longer depends on the npm package's provenance continuity for Open Code Review
- the fix does not weaken npm trust checks for other tools
- the installed executable comes from the project's canonical GitHub repository
- the `ocr` command remains unchanged
- CI detects release-asset naming or mise GitHub-backend regressions before they reach a fresh machine

### Trade-offs

- Open Code Review now has a tool-specific installation channel instead of sharing the npm channel with `npkill`
- CI downloads the Open Code Review binary, adding network and runtime cost to the shell job
- upstream release-asset naming is now part of the pc-setup compatibility surface

## Re-evaluation triggers

Reconsider this decision if:

- Open Code Review stops publishing official GitHub Release binaries
- release assets lose an adequate integrity/provenance verification path
- mise's GitHub backend can no longer install the supported platform assets reliably
- the upstream npm publication restores stronger, consistently enforced provenance and provides a material operational advantage over GitHub Releases
