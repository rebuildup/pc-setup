# ADR-0019: 専用WSLは非root SSHとWindows gatewayで接続する

- Status: Accepted
- Date: 2026-10-26
- Authority: [Issue #142](https://github.com/rebuildup/pc-setup/issues/142)、dotfilesの承認済み[分散ノード設計](https://github.com/rebuildup/dotfiles/blob/74/docs/adr/distributed-development-nodes.md)

新規WSL workerはADR-0016のWindows標準SIDごとの資源境界を維持する。接続経路は既存Windows VPN上の専用v4 TCP portproxyを先行し、WSL内で二つ目のVPNを実行しない。logical/instance identity、SSH hostkey、専用client key、Linux userと将来のMachine Identityは共有gatewayの接続属性から分離する。

Linuxの常用SSH userは非root・非sudo・公開鍵のみとする。固有host秘密鍵はguest内に残し、OS bootstrapに使うrootとSSH利用者を分ける。Windows PATH追加・interop・drive automountをdistro設定で抑制する。root所有のprivate設定/hostkeyと、sshdが対象userで読めるroot所有public authorized_keysを分ける。

gatewayは既存IP Helperを使用し、VPN IPv4/専用portとcontroller IPv4だけにFirewallを限定する。foreign mappingをadoptせず、所有manifest/hash/ACL/guest pinとfresh guest addressを確認したmappingだけを修復する。既存SSH service/22222や他distroの設定を変更しない。

WSL systemd unitとstatic gatewayだけではdistroの常時稼働を保証できない。Windows側の本人権限によるlifecycle・idle後再接続を別gateとし、初期SSH成功と分ける。認証cacheコピー、汎用broker、自作常駐scheduler、WSL MIの自動発行をこのPoCの条件にしない。共有VPNなので隣接workerのnetwork identity分離も未証明であり、管理鍵/他worker/管理socketの拒否を後続実測する。

WSLごとに独立VPN identityが必要になった場合、gatewayの依存や運用負担が許容できない場合、または実機の権限・稼働境界が成立しない場合は再評価する。
