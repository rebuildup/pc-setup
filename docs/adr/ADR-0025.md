# ADR-0025: machine-global / optional-host / project-local CLI の所有境界

- Status: Accepted
- Date: 2026-11-18
- Extends: ADR-0006, ADR-0009, ADR-0010
- Related: ADR-0023

## Context

pc-setupのmachine-global baselineには、すべての開発機で使う共通CLIに加えて、
特定クラウドや個別プロジェクトでだけ使うAWS CLI、Google Cloud CLI、
Supabase CLI、Playwrightまで含まれていた。
その結果、使用しない環境へのmandatory install、更新対象の肥大化、
project tool versionとglobal versionの責任の重複が起きる。

CLIのインストール位置、バージョン所有者、認証/権限の境界は独立した概念。
グローバルCLIが必ずグローバル認証を必要とするわけではなく、
project-localインストールが資格情報を自動的に隔離するわけでもない。

## Decision

CLIを用途と所有する正本で分類する。

1. **Machine-global core:** 複数プロジェクトの共通入口として頻用するCLIとruntime
   （mise、gh、Infisical、各種agent、汎用shellツール等）。
   そのバージョンの既定値は `mise.global.toml` と adopted lock が所有する。
   Project側のtoolchain定義はglobal既定値より優先する。
2. **Optional host capabilities:** AWS CLIとGoogle Cloud CLIのように、
   実行環境・SDK・利用するクラウドが限定されるツール。
   必要なホストだけに公式のインストール経路で導入する。
   単に認証があるから、という理由でプロジェクトへの実行ファイルの複製は要求しない。
3. **Project-local dependencies:** Supabase CLIやPlaywrightのように、
   プロジェクトのスキーマ、ビルド、テスト、マイグレーションと
   バージョン互換性が結びつくCLI。
   Consumerの `mise.toml` / `package.json` / toolchain lock等で版を管理する。
   CLIが必要なリポジトリ自身が宣言し、pc-setupは代わりに配備しない。

採用判断はツールごとに利用頻度、バージョン結合度、認証境界、
再現可能性、全ホストへの配備コストで行う。用途に合わない独自profile frameworkは作らない。

## Authentication and rollout boundary

- Cloudのアカウント/プロジェクトはAWSのnamed profile、gcloudのnamed configuration、
  Supabaseのproject linkなど公式の手段で明示的に選択する。
  実行時には現在の対象を確認し、本番操作を意図せず実行しない。
- Credential、token、service key、auth fileはGit/lock/mise configに保存しない。
  Providerのsupported user store、Infisical、workload identity/OIDCなど適切な管理を使う。
- 宣言除去は「今後bootstrapで必須にしない」という意味。
  既存のインストール済みCLIや資格情報を自動消去しない。
  移行後の未使用コピーの掃除は利用確認と別の安全な手順で行う。
- WindowsのWinGet `Google.CloudSDK` / `Amazon.AWSCLI` もmandatory package setから外す。
  既存のWindows利用者に削除を要求しない。
- NixOSのFHS `aws` / `gcloud` / `supabase` command wrapperは残す。
  これはproject-local/tool-on-demandの実行互換のためのlaunch surfaceであり、
  バイナリ導入・認証済み・共通必須を意味しない。

## Verification

- `mise.global.toml` と `mise.global.lock` の対象CLIは不在で、Playwrightの未参照sidecarも不在。
- Platform bootstrap / verifyの共通必須一覧から対象CLIを除外する。
- NixOSのcompatibility wrapperとmandatory command checksを混同しない。
- CLIが必要な個別projectの構成、利用案内、ローカル検証を各projectが所有する。
- lock採用/配備の仕組み自体（ADR-0010）を変更しない。

## Re-evaluation

- 任意ホストのツールが日常的な複数プロジェクトの必須基盤になったとき
- Global既定値を使うよりproject-localに固定しない方が安全・再現可能だと示されたとき
- CLI公式配布・認証・mise backendに破壊的な仕様変更があったとき
