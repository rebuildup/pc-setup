# ADR-0011: Tailscale device provisioning は Infisical runtime injection を使用する

- Status: Accepted
- Date: 2026-10-02

## Context

Windows host から WSL の SSH endpoint を localhost-only で公開しているため、同じ SSH endpoint をスマートフォン等の tailnet device から安全に利用するには Windows host 側の Tailscale connectivity と TCP forwarding を再現可能にする必要がある。

Tailscale device enrollment に reusable auth key を repository、shell history、plaintext file、persistent user environmentへ保存する運用は採用しない。pc-setup は portable secret の canonical authority として self-hosted Infisical を使用しており、secret contract と value authorityを分離する。

Tailscale は OAuth client secret を `tailscale up --auth-key` へ直接渡して node registration に使用できる。OAuth client は `auth_keys` scope と allowed tag を持つ必要があり、OAuth credential で登録した node は tag-owned になる。OAuth secret 使用時の node は既定で ephemeral なので、personal development machine では明示的に persistent registration を要求する。

既存 WSL SSH は Windows localhost 上で次を使用する。

- Ubuntu: `127.0.0.1:2222`
- Ubuntu2: `127.0.0.1:2223`

この localhost-only boundary は LAN へ直接広げず維持する。

## Decision

### Secret authority

Tailscale provisioning secret value は self-hosted Infisical のみを canonical authority とする。

repository は non-secret contract として以下だけを保持する。

- Infisical site/API endpoint
- project ID
- environment
- path
- required secret key name
- Tailscale advertise tag
- node registration parameters
- Serve listen/target mapping

current mapping:

- site: `https://secrets.rebuildup.dev`
- API: `https://secrets.rebuildup.dev/api`
- project: `d4c2fc09-a923-4a38-9cf4-b51769aadb76`
- environment: `prod`
- path: `/infrastructure/tailscale`
- secret: `TAILSCALE_OAUTH_CLIENT_SECRET`

secret value は Git、PR/Issue prose、logs、generated env fileへ materialize しない。

### Tailscale credential

Tailscale OAuth client は:

- `auth_keys` scope
- `tag:personal-device` を発行可能

で作成する。

fresh/unconnected Windows node は injected OAuth client secret を用いて:

```text
tailscale up --auth-key=<oauth-secret>?ephemeral=false&preauthorized=true --advertise-tags=tag:personal-device
```

相当で登録する。

script は secret value を表示しない。secret は `infisical run` の child process environment にだけ注入し、PowerShell historyやrepository-controlled fileへ保存しない。

既に `tailscale status --json` が `BackendState=Running` を返す machine は既存 node identity を保持し、再登録しない。これは manual/user-owned registration を secret automation が暗黙に置換しないためである。

### Windows installation

Tailscale Windows client は machine capability として pc-setup の desired state に含める。

Windows package installation は WinGet package `Tailscale.Tailscale` を使用する。network/remote-access foundation なので mandatory Windows package phase で fail-fast とする。

### WSL SSH forwarding

Tailscale Serve の raw TCP forwarderを使用して:

- tailnet TCP `2222` -> `tcp://127.0.0.1:2222`
- tailnet TCP `2223` -> `tcp://127.0.0.1:2223`

へ収束する。

WSL側の sshd / Windows localhost forwarding を LAN interface へ bind し直さない。

### Bootstrap boundary

root Windows bootstrap は Tailscale client を install するが、interactive Infisical login や Tailscale browser login を開始しない。

secret-backed enrollment は:

```powershell
.\platforms\windows-11\setup-tailscale.ps1
```

を明示的な post-bootstrap convergence command とする。

この command は既存の Infisical CLI authentication または externally supplied Infisical machine identity/tokenを使用する。Infisical auth が存在しない場合は fail closed し、managed Infisical Cloud、plaintext auth key、browser loginへ暗黙 fallback しない。

## Verification

Windows verification は secret value を取得せず:

- `tailscale` command presence
- current backend state
- configured Serve mapping

を確認する。

repository CI は:

- secret-free contract の required metadata
- OAuth secret key name
- persistent/preauthorized parameters
- localhost-only Serve targets
- setup script が secret literalを保持しないこと

を静的に検証する。

actual tailnet membership / OAuth scope / Infisical secret presence は live provider state なので repository CI の proof にはしない。

## Consequences

### Positive

- Tailscale credential の plaintext persistence が不要
- OAuth credential rotation を Infisical 側で一元管理できる
- WSL localhost-only SSH boundary を維持したまま mobile access を追加できる
- fresh/rebuilt Windows machine で同じ tailnet provisioning flow を再利用できる

### Trade-offs

- Infisical login/identity が provisioning trust root になる
- OAuth client で登録した node は user-owned ではなく tag-owned
- initial OAuth client creation / tag policy / Infisical secret creation は provider control-plane prerequisite
- already-connected node の identity drift は setup script が自動修復せず、意図しない re-registration を避ける

## Re-evaluate

次の場合に見直す。

- Tailscale が device provisioning 用のより短命な native workload identity mechanism を提供する
- Infisical 以外へ canonical secret authority を変更する
- WSL が tailnet node として直接管理され Windows Serve が不要になる
- mobile/MDM enrollment まで pc-setup が ownership を持つ
