# ADR-0024: converge の verify 用に launchctl print 1件だけを NOPASSWD で許可する

- Status: Accepted
- Date: 2026-11-17
- Extends: ADR-0012, ADR-0016
- Related: Issue #187

## Context

ADR-0016 の converge は OS スケジューラ(launchd LaunchAgent)から `platforms/macos/verify.sh` を非対話で実行する。verify.sh は Onishi LaunchDaemon の生存確認に `sudo /bin/launchctl print system/dev.rebuildup.pc-setup.onishi-keymap` を使う。

launchd コンテキストには TTY がなく、sudo の timestamp credential も存在しないため、この呼び出しは毎回 `sudo: a password is required` で失敗し、status.json の verify が常に fail になる。手動実行は TTY のパスワードプロンプトで成功するため、問題は自動実行経路に限定される。

検討した選択肢:

- verify を sudo 不要に書き換える — `launchctl print system/...` は root 権限が必須で、回避できない
- converge で verify を skipped 扱いにする — verify が事実上手動専用になり、自動収束の検証価値が失われる
- sudoers.d に限定的な NOPASSWD を置く — 自動実行と手動実行で同じ検証が使える

## Decision

`install-keyboard.sh` が `/etc/sudoers.d/pc-setup-verify` を配置する。

- 許可対象は `/bin/launchctl print system/dev.rebuildup.pc-setup.onishi-keymap` の完全一致 1 件のみ。ワイルドカード・他コマンド・他サービスは許可しない
- 対象ユーザーは installer 実行者(`id -un`)に限定し、`%admin` などのグループ指定は使わない
- ファイル名に `.` を含めない(sudo は sudoers.d 内のドット入りファイル名を無視する)
- install 前に `visudo -cf` で構文検証し、失敗時は配置しない
- 権限は `root:wheel 0440`

この許可は読み取り専用の launchd 照会 1 件に限定され、書き込み・サービス制御・他の特権操作は含まない。kanata / containers の verify は converge の対象外であり、手動実行時のパスワードプロンプトを維持する。

## Consequences

- converge LaunchAgent が TTY なしで verify を完走でき、status.json の verify が実際の検証結果を反映する
- 許可範囲が verify の 1 コマンドに限定されるため、sudoers.d の追加による攻撃面の拡大は最小限
- installer を実行していないマシンでは converge の verify は従来通り失敗する。再現には `install-keyboard.sh` の実行が前提(ADR-0012 の導入手順に含まれる)
