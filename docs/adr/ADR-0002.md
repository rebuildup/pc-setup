# ADR-0002: Ubuntu/WSL2 Baseline Toolchain and Installation Channels

- Status: Superseded
- Date: 2026-09-23
- Investigation date: 2026-09-23
- Superseded by: ADR-0006

## Supersession note

The installation-channel choices below record the original Ubuntu/WSL bootstrap. ADR-0006 replaces the per-tool imperative installation model with mise as the common orchestrator. WSL filesystem/workspace boundaries and the separation of credentials from repository state remain relevant.

## Context

Ubuntu/WSL2 は、AI coding agent、Git/GitHub操作、Rust/C/C++、JavaScript/TypeScriptの開発を行う主要なLinux環境として使う。

fresh distributionで毎回install sourceを探し直すと、Ubuntu archive版、古いnpm package、非公式installer等が混在しやすい。特に頻繁に更新されるClaude Code、OpenCode、GitHub CLI、Worktrunkは、実際の普段使いに近いcurrent stableを公式経路から導入する方が保守しやすい。

一方、authenticationをbootstrapへ埋め込むとsecret漏えいとmachine identity混同の原因になる。

## Decision

### 1. Target environment

- WSL2上のUbuntuを対象とする。
- development repositoryはLinux filesystem側の `~/src` を標準workspaceとする。
- `/mnt/c` 等のWindows-mounted filesystemは、通常のbuild/watch/git workspaceとして使用しない。
- WSL distributionはWindows側とは別のdevelopment machineとしてtool installationとauthenticationを行う。

### 2. Base packages use Ubuntu APT

compiler/build foundationと小型CLIはAPTで管理する。

baselineには少なくとも次を含む。

- Git / curl / wget / CA certificates / GnuPG
- build-essential / CMake / Ninja / Clang / pkg-config / OpenSSL headers
- jq / ripgrep / fd-find / fzf / bat / tree
- zip / unzip / xz / rsync
- ShellCheck
- Python 3 + venv
- OpenSSH client

Ubuntu固有のbinary name差異はuser-local symlinkで吸収する。

- `fdfind` -> `~/.local/bin/fd`
- `batcat` -> `~/.local/bin/bat`

### 3. GitHub CLI uses GitHub's official APT repository

Ubuntu archiveの`gh`ではなく、GitHub CLI maintainersが提供するDebian/Ubuntu package repositoryを登録して導入する。

理由:

- upstreamがofficial packageを提供している
- current GitHub APIとのcompatibilityを追いやすい
- 2025年以降upstreamはDebian/Ubuntu community packageよりofficial packageを推奨している

### 4. Rust uses rustup stable

Rust / Cargoは`rustup`のstable toolchainを使う。

system APTのRust compilerをcanonicalにしない。

### 5. Worktrunk uses Cargo

Worktrunkは:

```bash
cargo install worktrunk
wt config shell install
```

をcanonical installation pathとする。

WorktrunkはGit worktree操作のdefault frontendであり、runtime/security isolation boundaryではない。

### 6. Bun uses the official installer

Bunはofficial installerのstable channelを使う。

```bash
curl -fsSL https://bun.sh/install | bash
```

### 7. Claude Code uses the native Linux/WSL installer

Claude Codeはnative installerを使う。

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

npm版をcanonical installation pathにしない。

authenticationはinstall後に対話的に行う。

### 8. OpenCode uses the official stable installer

OpenCode stableは:

```bash
curl -fsSL https://opencode.ai/install | bash
```

をcanonical installation pathとする。

provider authenticationはinstall後に:

```bash
opencode auth login
```

で行う。credential valueはrepositoryへ保存しない。

OpenCode v2など別channelへ切り替える場合は、実際のmain environmentとして採用するときにこのADRをreviseする。

### 9. Frequently updated user tools track stable channels

Claude Code、OpenCode、Bun、Rust stable、Worktrunk等は、特別なcompatibility reasonがない限りpoint versionをrepository desired stateとして固定しない。

必要に応じて `verify.sh --snapshot` の出力を `snapshots/` へ保存する。

## Verification

fresh Ubuntu/WSL2上で最低限次を確認する。

```bash
./platforms/ubuntu-wsl/bootstrap.sh
exec bash
./platforms/ubuntu-wsl/verify.sh
```

manual authentication:

```bash
gh auth login
gh auth setup-git

claude

opencode auth login
opencode auth list
```

## Re-evaluation triggers

- upstreamのofficial installation methodが変更・deprecatedになった場合
- Ubuntu packageがofficial upstream channelと同等以上のfreshness/maintenance guaranteeを持つ場合
- Worktrunk以外のworkspace managerをmain workflowへ採用する場合
- OpenCode stable/v2等のchannel policyを変更する場合
- user toolをpinしないと再現性またはcompatibilityを維持できない具体的障害が発生した場合
- WSLではなくnative Windows/Linux/macOSがmain development environmentへ変わった場合
