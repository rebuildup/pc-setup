# ADR-0009: Windows desktop applications converge best-effort and verify strictly

- Status: Accepted
- Date: 2026-09-23
- Extends: ADR-0004, ADR-0006, ADR-0008

## Context

Windows bootstrap uses several third-party GUI installers through WinGet. In practice, individual vendor installers can fail for reasons unrelated to the rest of the machine setup.

Two real-machine failures demonstrated the same structural problem:

- Notion's WinGet-delivered Setup EXE terminated with `0xC0000005`.
- Microsoft Teams terminated with `0x80070002`.

When these applications are part of mise's mandatory `[bootstrap.packages]` phase, one GUI installer failure aborts the remaining bootstrap, including unrelated developer tooling.

The desired state should remain strict, but bootstrap progress should not be coupled to the reliability of every desktop vendor installer.

## Decision

### 1. Bootstrap foundations remain fail-fast

Packages required to establish or materially support the development machine remain in the mandatory mise package phase.

Current Windows foundation includes:

- Git
- PowerShell
- .NET SDK
- Visual Studio
- Android Studio
- Google Cloud SDK
- AWS CLI

Git and mise themselves remain bootstrap dependencies.

### 2. Desktop applications use a shared best-effort inventory

Non-foundational desktop applications are declared once in `platforms/windows-11/apps.psd1`.

The Windows root adapter reads this inventory and processes each WinGet application independently.

For each application:

1. detect an existing installation,
2. skip if present,
3. otherwise invoke exact-ID WinGet installation,
4. record a warning on failure,
5. continue to the next application.

A single desktop application failure MUST NOT abort portable tooling or the remaining application convergence.

### 3. Verification remains strict

`platforms/windows-11/verify.ps1` reads the same inventory.

Missing desired desktop applications are verification failures even though installation is best-effort.

This separates two guarantees:

- bootstrap continuity: make as much progress as possible,
- desired-state correctness: report every missing required application at the end.

### 4. Special installation boundaries remain separate

Notion continues to use the official MSIX boundary from ADR-0008.

Microsoft Store-specific applications such as ChatGPT and Microsoft PC Manager continue to use the explicit Store boundary.

Vendor child products such as After Effects, Illustrator and Cubase retain their existing manager/manual verification model.

## Consequences

### Positive

- one broken GUI installer no longer blocks unrelated machine setup,
- desktop desired state remains explicit and verifiable,
- bootstrap and verification share one inventory instead of duplicating application lists,
- future application additions have one canonical declaration point.

### Trade-offs

- bootstrap can finish with warnings while the machine is not yet fully converged,
- final verification becomes the authoritative completeness gate,
- some applications may require a later rerun or manual vendor repair.

## Re-evaluation triggers

Reconsider this decision if:

- mise gains a reliable per-package continue-on-error policy with final aggregate reporting,
- WinGet provides transactional batch convergence suitable for this workflow,
- Windows moves to a different declarative package/configuration system,
- an application becomes a true bootstrap dependency rather than a desktop convenience/tool.
