# ADR-0001: Personal Environment as Platform Guide + Bootstrap + Verify

- Status: Accepted
- Date: 2026-09-23
- Superseded by: None

## Context

この repository の目的は、不特定多数向けのセットアップ例を集めることではなく、maintainer が実際に使っているPC・OSごとの開発環境を将来の新規PC、再インストール、追加WSL distribution等で再現できる状態にすることである。

READMEだけを canonical source にすると、記述は理解しやすい一方で手順漏れや drift を機械的に検出できない。逆に bootstrap script だけを canonical source にすると、installer変更や部分失敗が起きたときに「何を目的としていたか」「どこまで手動作業なのか」が読めなくなる。

また、常に最新版を追うCLIと、ある時点の実環境のversion inventoryを同じものとして扱うと、snapshotのためだけに不要なversion pinが増え、普段使いの環境から離れていく。

## Decision

### 1. Repository is the durable personal environment source of truth

OS / platform ごとの desired development environment を repository-controlled state として管理する。

会話履歴、端末の現在状態、private note、shell historyだけを唯一の再現根拠にしない。

### 2. Each active platform uses three complementary layers

active platform は原則として次を持つ。

1. `README.md` — 人間向けの目的、順序、manual step、troubleshooting
2. `bootstrap` — machine stateをdesired stateへ近づける再実行可能なautomation
3. `verify` — expected command/capabilityが存在するか確認するdeterministic check

いずれか1つを他の代替にはしない。

### 3. Desired state and version snapshots are separated

desired state は「どのinstallation channelを採用するか」「どのcapabilityを必要とするか」を定義する。

時点依存のversion inventoryは `snapshots/` に置く evidence とし、それだけを理由に tool version を固定しない。

compatibility requirementや破壊的変更回避のためにpinが必要になった場合は、tool単位で明示し、長期的なpinならADRへ記録する。

### 4. Credentials remain outside the repository

bootstrapはtoolの導入までを自動化してよいが、account loginやsecret provisioningは原則として明示的manual stepにする。

password、token、API key、cookie、SSH private key、provider auth database等はcommitしない。

### 5. Automation must remain recoverable from documentation

external installerの仕様変更などでbootstrapが失敗しても、fresh readerがplatform guideとofficial sourceから意図を再構成できるようにする。

script内だけに重要なsetup reasonを隠さない。

## Consequences

### Positive

- 新規WSL distributionやPC交換時に同じ開発環境を再構築しやすい。
- documentation driftとmachine driftをverifyで検出できる。
- latest追従ツールを不必要にpinせず、実測versionも別途保存できる。
- auth情報をrepositoryへ持ち込まずにsetup automationを進められる。

### Trade-offs

- READMEとscriptの双方を同期するmaintenance costがある。
- external installer自体の可用性や将来互換性はrepositoryだけでは保証できない。
- machine-specific設定のすべてを完全自動化することは目的にしない。

## Re-evaluation triggers

- declarative environment managerが、可読なdocumentation・safe bootstrap・verificationを同等以上に統合できる場合
- setup対象が個人環境ではなく複数人向けの配布環境へ変わる場合
- credential managerとの安全な自動provisioningをcanonicalに採用する場合
