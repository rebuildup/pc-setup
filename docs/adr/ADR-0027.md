# ADR-0027: herdr-t3 は検証済み ref の独立リリース配置で導入・更新・復旧する

- Status: Accepted
- Date: 2026-11-22
- Related: Issue #220, rebuildup/herdr-t3#6, rebuildup/herdr-t3 ADR-0004

## Context

herdr-t3 は browser/PWA + ローカル Bun ブリッジ (`127.0.0.1:4737`) として配布され、デスクトップシェルや常駐サービスを持たない (herdr-t3 ADR-0004)。pc-setup は macOS と Windows 11 の双方で、検証済みリリースの導入・更新・起動・verify・ロールバックを再現可能にする必要がある。開発チェックアウト (Vite HMR、port 4738) とは同時運用できなければならない。

## Decision

- 管理 state dir は `~/.local/share/herdr-t3` (Windows は `%LOCALAPPDATA%\herdr-t3`)。配下に `releases/<ref>/` の ref 別独立 checkout を置き、`current` ファイルが選択中リリースを指す。
- 導入対象は `v*` タグまたは完全 SHA のみ。dev ブランチや未承認の release 候補は自動選択しない。既定は origin の最新 `v*` タグ。
- build (`mise install --locked` + `bun install --frozen-lockfile` + `bun run build`) は install/update 時のみ。起動時ビルドは行わない。
- `current` の切替は build 成功後に限る。失敗時は選択・稼働中リリースを維持する。`previous` に記録した旧リリース dir を残し、rollback は pointer flip のみ (再 build 不要)。
- launch は冪等: `/api/health` が応答すれば bridge を再利用してブラウザのみ開く。他プロセスが port 4737 を占有する場合は乗っ取らず失敗とする。
- verify は install 状態 (ref, dist, bun) を必須とし、`--live` で `/api/health` の `ok` / `herdr.reachable` / version・commit を追加判定する。
- Linux の herdr TUI 運用は変更しない。

## Consequences

- リリースごとに独立 dir を持つため disk 使用量は増えるが、rollback が再 build なしで即時に行える。
- Windows の named pipe / mirror pane 対応 (herdr-t3#6) が未完の間、Windows での `verify --live` は `herdr.reachable=false` を返しうる。これは既知の制限として Issue #220 の受入で追跡する。
- 実機 (macOS / Windows 11) での導入→起動→verify→更新→rollback の受入証跡は Issue #220 で管理する。
