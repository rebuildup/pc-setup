# ADR-0028: herdr-t3 は Electron デスクトップアプリとして導入・検証する

- Status: Accepted
- Date: 2026-11-22
- Supersedes: ADR-0027
- Related: Issue #220, rebuildup/herdr-t3#21, rebuildup/herdr-t3 ADR-0005

## Context

herdr-t3 の配布方式が browser/PWA + ローカル Bun ブリッジから Electron
デスクトップアプリ (macOS .app / Windows 11 インストーラ) へ変更された
(herdr-t3 ADR-0005)。pc-setup#220 の install/launch/verify/rollback は
ブラウザ起動を前提としていたため、アプリ本体の導入・起動・検証へ改訂する。

## Decision

- 導入対象は検証済みリリースのデスクトップアプリ成果物 (macOS `.app` /
  Windows インストール可能パッケージ) であり、`v*` タグまたは固定 SHA に
  対応する。開発ブランチや未承認 RC は自動導入しない。
- state dir・`current`/`previous` pointer・更新失敗時の現行維持・
  rollback (pointer flip) の構造は ADR-0027 を踏襲するが、単位は
  「ビルド済みアプリ成果物」とする。
- 起動は OS の通常導線 (macOS は `.app` を `open`、Windows は
  ショートカット/`Start-Process`)。Bun ブリッジやブラウザの別途起動を
  前提にしない。アプリは Main プロセス内に bridge core を持ち herdr
  socket へ直接接続する。
- verify はアプリ成果物の存在・バージョンと、可能ならアプリの
  `/api/health` 相当 (IPC health) またはプロセス生存で Herdr 接続可否を
  判定する。実 Herdr への接続受入は herdr-t3#22 の実機証跡で管理する。
- macOS の署名/notarize と Windows の SmartScreen 警告は、個人利用の
  実配布方式 (unsigned local build 等) に合わせて扱い、ストア配布は
  前提にしない。
- Linux の herdr TUI 運用は変更しない。

## Consequences

- `components/herdr-t3/` はアプリ成果物モデルへ改訂済み: install は
  pin された ref を checkout して `bun run desktop:pack`
  (electron-builder) で `.app` / `win-unpacked` を構築し、launch は
  生成物を直接起動する。Bun・ブラウザ・ローカル HTTP サーバーの
  常駐は不要。
- herdr-t3 側で packaging (electron-builder 設定、アイコン、
  macOS/Windows 成果物レイアウト) が確定してから pc-setup 側の
  install/verify 実装を完成させる。
