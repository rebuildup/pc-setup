# ADR-0022: macOSのディスク使用量分析はWizTreeMacをmiseで管理する

- Status: Accepted
- Date: 2026-11-10
- Related: ADR-0005, ADR-0006, ADR-0012

## Context

WindowsではWizTreeをWinGetのGUI baselineに含めている。一方、macOS候補の計画では、WizTreeをWindows専用ユーティリティとして自動移行対象から外していた。

2026年9月にAntibody SoftwareからWizTreeMacが提供された。利用者はmacOSでもWizTreeを利用することを明示的に選択したため、他のWindowsアプリの機械的移行ではなく、macOS独自の採用判断として扱う。

## Decision

macOSのディスク使用量分析には公式WizTreeMacを採用する。

- 配布元はAntibody Softwareの公式サイト `diskanalyzer.com` とし、同社Homebrew Tapの公開するDMGとSHA-256を採用根拠にする。
- `mise.global.toml` の `[bootstrap.packages."macos-app:wiztreemac"]` に、`version = "1.00"`、DMG URL、SHA-256、`artifact = "WizTreeMac.app"`、`os = "macos"` を宣言する。
- GUIアプリのインストール責任は既存のmise bootstrapに統一する。Homebrewのコマンドを別の必須bootstrap経路として増やさない。
- `macos-app` は新リリースを自動検出できないため、versionとchecksumを明示する。更新時は配布元/Tapの新しいversion・DMG URL・SHA-256を検証し、宣言と実機を更新する。
- Windowsは既存の `AntibodySoftware.WizTree` WinGet宣言を継続し、LinuxにはWizTreeMacを導入しない。

## Correction to initial channel decision (#172)

このADRの最初の版では公式Homebrew Tapを `brew-cask` で直接利用することを決めた。しかしmacOS arm64・mise v2026.10.25の実機で `Casks/wiztree.rb:5` の `version.tr(".", "_")` が `Version` オブジェクトで失敗し、`mise bootstrap packages apply` 全体が停止した。Homebrew本体での導入手順を別途強制する案は採らない。

代替の `macos-app` は、同じmiseのbootstrap managerとしてv2026.10.25にも存在し、署名済みの外部インストーラーに依存せずDMGをchecksumで検証できる。ただし自動リリース追従はない。将来Tap側・mise評価器側の互換性が直れば、公式Tapを再評価する。

## Security and permission boundary

元のTap caskは `diskanalyzer.com` のDMGとSHA-256を宣言する。miseの `macos-app` へ同じ情報を転記し、ダウンロードをchecksumで検証する。直接配布経路とTapの信頼性は継続評価対象とする。既存アプリは `adopt = true` で同一内容の場合だけ管理下へ移し、異なる内容を暗黙に上書きしない。

macOSでは、Full Disk AccessとAdministratorモードは別の権限である。インストールやbootstrapの成功を、これらの権限の許可と同一視しない。必要時に利用者がSystem SettingsとアプリUIで明示的に許可する。pc-setupはTCCデータベースやライセンス情報を変更・保存しない。

## Verification

- 宣言とOS条件: `mise.global.toml` の `bootstrap.packages` と `macos-app:wiztreemac` の完全なDMG/SHA-256情報
- Mac上の管理状態: `mise bootstrap packages status --json`
- インストールの実在: `/Applications/WizTreeMac.app`
- 権限と実効性: 実機で保護ディレクトリをスキャンし、必要なアクセスが得られることを確認する

macOS実機での権限付与はCIから検証できない。DMG URLの実際の到達性、インストール、保護領域スキャンは実機で確認する。

## Re-evaluate

- 公式Tapの配布元や署名/ハッシュの検証条件が変わった場合
- miseの第三者Tap評価器が修正された、macOS公式caskへ移管された、または公式インストーラが大幅に変わった場合
- 実機で使用しなくなりmachine-global baselineが不要になった場合
