# ADR-0017: 専用SSH待受はSYSTEMの専用起動タスクで管理する

- Status: Accepted
- Date: 2026-10-26
- Scope: Issue #138 / dotfiles #74 のcontroller接続経路

## Context

前面OpenSSH PoCは専用公開鍵とhost pinで接続できたが、起動元の一時process/job終了によりlistenerが失われた。通常利用にはOSが管理する起動主体が必要。既存標準sshd serviceや既存SSH設定を採用・変更する権限はない。任意名OpenSSH serviceの互換性を仮定せず、Windows標準Task Schedulerのservice-account実行を使う。

## Decision

pc-setupが専用boot taskと別のadmin-owned runtimeを所有する。タスクはSYSTEMでWindows同梱OpenSSHをforeground `-D` 起動し、元の専用enrollment/key/config/Firewallをそのまま使う。タスクにpassword/token/private keyを格納せず、管理者とSYSTEM以外にtask/sourceの変更権限を渡さない。PowerShellはnative x64、NoProfile、machine-only module探索とする。

Installは所有source・enrollment hash・SIDを固定してtaskを登録する。Verifyはtask定義/ACL・manifest・source/hashを照合し、foreign/partial/driftを上書き・adoptしない。Startは空listenerを要求する。taskはVPN addressの準備を待ち、失敗時の再実行をTask Schedulerに限定する。標準sshdはStopped/Manualを維持する。

元のTailscale profileをログアウト後も動かす場合は公式unattended設定を別の明示操作として適用し、ノードID/IP/control server/必要設定の同一性を検査する。新loginやlogin-server変更を復旧手段にしない。

## Evidence and limits

source/pure testsとTASK_VALIDATE_ONLYによるOS schema検査は、SYSTEMでの実SSH認証やOS再起動の証明ではない。listener・専用鍵nonce・Herdr再接続を別途実測する。private log容量を運用確認する。controller管理者の接続用であり、標準worker/WSL分離の証明には使わない。

taskによるWindows OpenSSH認証が当該OSで成立しない、権限不足を理由に認証緩和が必要、または正規boot復帰ができない場合は方式を再評価する。既存serviceや管理鍵へ暗黙fallbackしない。停止は所有taskだけ、削除・元enrollmentのUndoは別手順とする。
