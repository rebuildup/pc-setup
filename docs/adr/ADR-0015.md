# ADR-0015: Windows の Rust toolchain も mise が管理する

- Status: Accepted
- Date: 2026-10-31
- Extends: ADR-0006

## Context

Linux と macOS の Rust は `mise.global.toml` の `rust` 宣言で mise が管理していた。Windows だけが例外で、2026-10-17 に次の経緯で mise から Rust を外していた。

- Windows の Rust toolchain は、rustup (`rustup.rs`) で個別に導入した既存のインストールを正本としていた。
- mise が `rust@stable` を自動 install した際、既存 rustup の toolchain と競合し、rollback の結果として `rustc.exe` / `cargo.exe` が消えた。mise shim を 1 回呼ぶだけで起きた。
- 事故への対処として、`mise.global.toml` の `rust` を `os = ["linux", "macos"]` に限定し、Windows 用の config には `disable_tools = ["rust"]` を注入していた。

この状態には二つの問題があった。

- 同じ Rust toolchain について、宣言 (mise) と実装 (rustup) が食い違い、「どちらが正本か」が machine ごとに違う。
- Rust CLI 11 本 (cargo-tauri / wasm-pack / just / llmfit / rtk / cargo-ndk / cargo-generate / cargo-compete / cargo-cleaner / cargo-update / rust-mcp-filesystem) が `cargo install` の結果として `%USERPROFILE%\.cargo\bin` に残り、pc-setup が把握していない tool になっていた。

## Decision

### 管理者は mise とする

Rust toolchain の管理者は mise とする。宣言は `mise.global.toml` の `rust = "stable"` だけで、Windows も含め全 OS 共通とする。

rustup は廃止しない。mise の rust backend が rustup を storage / installer として使う実装であるため、rustup は toolchain の置き場所として残る。変わるのは「toolchain を選ぶ層」で、そこは mise の設定だけとする。

### Windows の rustup home と Cargo home は mise の data dir に置く

`scripts/windows-mise-config.ps1` が Windows 用の config に `[env]` として次を注入する。

- `MISE_RUSTUP_HOME` / `RUSTUP_HOME` = `%LOCALAPPDATA%\mise\rustup`
- `MISE_CARGO_HOME` / `CARGO_HOME` = `%LOCALAPPDATA%\mise\cargo`

これにより machine 上の rustup home と Cargo home が 1 つずつに定まる。旧 `%USERPROFILE%\.rustup` と `%USERPROFILE%\.cargo` は廃止し、`%USERPROFILE%\.cargo\bin` は User PATH から外す。mise が作る shim が同じ名前の proxy を提供するため、PATH 上の優先順位は mise shim が先になる。

### Rust の自動 install は止める

Windows 用の config は `auto_install_disable_tools = ["rust"]` を持つ。shim の実行が background で toolchain を install し始めることを許さない。toolchain の導入と更新は `mise install rust` / `mise install rust@<version>` での明示的な操作だけで行う。

### toolchain 選択の正本は mise の設定

選択の優先順位は次の通り。

1. project の `mise.toml` の `rust` 宣言
2. project の `rust-toolchain.toml` (`idiomatic_version_file_enable_tools = ["rust"]` で mise が読む)
3. machine global の `mise.global.toml` の `rust = "stable"`

mise は選択した toolchain を `RUSTUP_TOOLCHAIN` として export する。rustup は `RUSTUP_TOOLCHAIN` を `rust-toolchain.toml` より優先するため、project の pin がそのまま rustup 互換の選択になる。

### Rust CLI は mise の cargo backend で宣言する

`cargo install` で入れた 11 本は `mise.global.toml` の `cargo:` tool として宣言する。`depends = ["rust"]` により、toolchain が先に入る。Windows 固有の 10 本 (cargo-clean-all を除く) は `os = ["windows"]` で他 OS に波及させない。

git 由来 の 2 本は tag で固定する。`rtk` の repository は複数 crate を持つため `crate = "rtk"` を明示する。

## Consequences

- machine 上の Rust は mise の設定だけで決まる。`rustup default` による暗黙の切り替えは無い。
- toolchain の追加・更新は mise 経由になる。既存 toolchain (1.42.0 など) は新しい rustup home に無いので、使いたいものは明示 install する。
- Cargo の registry cache は移行時に旧 `%USERPROFILE%\.cargo` から新 Cargo home へ移す。以後の cache 成長は新 Cargo home 側になる。
- Rust CLI の更新は `mise install` 経由になる。`cargo install --force` による個別更新は行わない。
- mise の rust backend が rustup を使い続ける限り、rustup 自体の更新経路は残る。

## Re-evaluate

- mise の rust backend が rustup を前提としない実装 (独自 toolchain 配置) へ変わった場合
- Rust の toolchain として rustup 単体を正本に戻す必要が生じた場合
- mise の Rust 自動 install が安全になり、`auto_install_disable_tools` を外せる場合
