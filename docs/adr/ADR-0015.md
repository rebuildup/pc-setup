# ADR-0015: Headscale control plane を既存 VPS に独立配置する

- Status: Accepted (PoC scope)
- Date: 2026-10-24

## Context

開発 node の相互接続には user dotfiles と別の machine/network provisioning 境界が必要である。既存 Infisical VPS は Docker/Compose があり TCP 80/443 を利用できるが、secrets control plane を停止させずに評価する必要がある。

## Decision

pc-setup が `infrastructure/headscale` の source と日本語 runbook を所有する。独立 Compose project/directory `/srv/devnode-headscale` に official Headscale 0.29.6、SQLite と machine-local named volume を置く。初期 PoC の server schema と合わせて image version を固定し、通常の user CLI version policy とは区別する。config と deny-all grants policy のみを Git に置く。Noise/ACME/DB/admin credential は machine-local で、dotfiles/home や Git に展開しない。

DNS-only の公開 hostname と native ACME HTTP-01 を使い、TCP 80/443 だけを公開する。既存 Infisical compose や cloudflared は変更しない。embedded DERP は導入せず外部 default DERP map を利用する。node enrollment、role policy、credential issuance、scheduler/broker、自動 tailnet 切替は別 scope とする。運用前に DNS/firewall/TLS と Infisical の無停止を実測する。

## Consequences / reconsideration

追加 DB/proxy/daemon が不要な最小 PoC だが、Infisical と host の failure domain を共有し、外部 relay/STUN に依存する。既存接続の無期限継続を保証しない。独立 availability、resource contention、private relay 要件、Headscale schema/security update、または role policy の導入時に再評価する。upgrade は backup/restore と version 固定 schema の確認を伴う。所有権 marker と拒否型 materialization は foreign state を暗黙に採用しないための境界であり、自動 upgrade mechanism は設けない。

根拠・具体的な validation/rollback は [runbook](../../infrastructure/headscale/README.md) を参照する。
