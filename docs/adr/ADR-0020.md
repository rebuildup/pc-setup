# ADR-0020: WSL gatewayは対話ログオン後に安全に再調整する

- Status: Accepted
- Date: 2026-10-30
- Authority: [Issue #142](https://github.com/rebuildup/pc-setup/issues/142)、[ADR-0019](./ADR-0019.md)

## Context

専用WSLはWindows operatorのInfisical user login cacheからworker credentialを取得し、memory-only SecureStringで専用worker processへ渡す。Task SchedulerのS4U logonはnetwork accessとuser encrypted-file accessを提供しない。また、別ユーザーのS4U task登録は登録時passwordを要求しうる。保存passwordやcredential cacheの複製はこの境界に合わない。

## Decision

ログオン後の復帰に限り、operator本人のAtLogOn Interactive taskをHighestで登録する。taskはAdministrator/SYSTEMが変更できるProgramData bundleを実行する。bundleは固定commitのworker script、hash検証済みInfisical CLI、監査済みbounded SecretCapture helperを含み、sourceやtask actionのdriftを拒否する。起動時に現在のoperator user cacheから専用worker secretだけを得て、SecureStringでgateway repairへ渡す。secretをargv、environment、task definition、file、resultへ出さない。

Taskは一度だけ実行し、自動retry・再起動・WSL停止をしない。operatorがログインする前のheadless recoveryは対象外。失敗時はsecretを含まないresultだけを保護directoryへ書き、状態を自動変更せず止める。明示的なsync/installはreviewed clean commitとinstaller hashを要求する。Task撤去はTaskだけに限定し、WSL hold/gateway/firewallを削除しない。

## Consequences and evidence gates

Task登録・ACL・operator logon・idle/reboot後のSSH再接続はそれぞれ実機で検証する。ログオン前の利用が必要なら、公式なpasswordless user credential integrationまたは別のOS管理方式を調査して再評価する。S4Uと保存passwordは採用しない。
