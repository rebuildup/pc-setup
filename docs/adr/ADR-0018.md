# ADR-0018: macOSの専用開発ノード待受をユーザーLaunchAgentで管理する

- Status: Accepted
- Date: 2026-10-26

## Context

foregroundの専用sshdとHerdr serverは、起動元のagent processが終了すると失われる。端末固有の鍵や既存の標準sshdを変更せず、ユーザーがログインした開発ノードで待受を復帰させる必要がある。

## Decision

pc-setupが、独立したinstance UUIDごとにSSHとHerdrの2つのユーザーLaunchAgentを所有する。`gui/<uid>`のみに登録し、root LaunchDaemonや既存のHerdr default sessionは管理しない。認証情報・鍵・Herdr設定の同期は行わない。

実行はPython標準ライブラリとlaunchctlを利用する。OS設定用のprivate manifestに絶対pathとSHA256を記録し、runtime workerを所有stateへ配置する。workerはPython isolated modeで起動し、各起動時に所有ファイルと入力hashを検査してから、必要な環境変数だけでexecする。入力の更新は自動採用せず明示的な再登録を必要とする。

LaunchAgentはRunAtLoad、KeepAlive、ThrottleInterval 60秒を使用する。VPNがまだ起動していない場合、sshdの失敗をlaunchdが再試行する。認証や通信の成功はstatusだけで判定せず、SSH host pinとHerdrのnonceによる別のE2E検証を必要とする。

同じUUIDの操作はprivate lockで直列化する。既存の無関係なplist、異なる実行元の読み込み済みjob、所有ファイルのdriftを拒否する。partial bootstrapは所有manifestを保持し、再実行・status・removeで扱える。removeは所有jobのみをbootoutし、鍵や入力設定を残し、ログを別のprivate archiveへ保持する。

## Limits and re-evaluation

GUIログイン前やログアウト中の可用性は保証しない。ホストの再起動・ログイン後復帰は実機検証が必要。launchctl printは安定APIではないため、既知のpath/state形式を認識できない場合は操作を停止する。macOS更新時に再検証する。

同じOSユーザーが悪意を持つ場合の隔離境界にはしない。rootと本人の権限、同じユーザーによる管理ファイルの同時編集がないことを前提とする。設定やtoolの更新時には入力hashを再確認して明示的にremove/applyする。
