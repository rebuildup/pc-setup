# ADR-0010: machine-global tools use a continuous update train

- Status: Accepted
- Date: 2026-09-25
- Extends: ADR-0001, ADR-0006

## Context

`pc-setup` declares fast-moving machine-global developer tools in `mise.global.toml`. Many declarations intentionally use rolling selectors such as `latest` or `stable`.

Resolving those selectors independently on every machine causes machine drift and repeated per-tool update prompts. Reducing update frequency is not the goal. Normal releases should be adopted frequently, while human attention is reserved for updates that fail verification.

## Decision

### 1. Separate desired, adopted, and installed state

`mise.global.toml` is desired policy. `mise.global.lock` is adopted state. Each machine converges its installed state to the committed adopted state instead of independently resolving fuzzy selectors.

A selector such as `latest` remains unbounded. A bounded selector such as `node = "24"` continues to advance only within that lane.

### 2. The update train owns upstream resolution

A scheduled GitHub Actions workflow runs daily and resolves fuzzy selectors with `mise lock --global --bump` for Linux x64, Windows x64, macOS x64, and macOS arm64.

The train imposes no minimum release age. It MUST NOT modify `mise.global.toml`; source-policy changes remain normal repository changes.

### 3. Adoption requires exact-SHA verification

When resolution changes `mise.global.lock`, the train:

1. writes the generated state to an automation-owned branch,
2. opens or refreshes one maintenance PR,
3. dispatches repository CI against that exact branch head,
4. requires CI success on that exact SHA,
5. verifies that the PR head still equals the validated SHA,
6. merges using a merge commit.

Resolution or CI failure does not advance adopted state. The PR remains as durable evidence.

### 4. Generated adopted state has a narrow delivery exception

The normal project-init release path remains authoritative for source, policy, bootstrap, verification, and workflow changes.

The continuous update train may update `main` outside a release branch only when:

- the repository-owned train produced the change,
- the only changed path is `mise.global.lock`,
- repository CI succeeded on the exact head SHA,
- the PR head still matches the verified SHA,
- merge-commit history is retained.

This exception does not authorize agents or humans to bypass the release path for ordinary changes.

### 5. Machines consume adopted state strictly

The global mise adapters expose `mise.global.lock` beside the installed global configuration. When a committed lockfile exists, the final machine-global install uses mise locked mode so missing or incomplete lock entries fail instead of silently resolving a different upstream version.

The pre-authentication GitHub CLI bootstrap may remain unlocked because it establishes authentication required by later GitHub-backed operations. The final locked install reconciles it to adopted state.

### 6. Notification ownership follows update ownership

For tools whose update lifecycle is owned by pc-setup, vendor self-update or update-check prompts SHOULD be disabled only when an official supported control exists.

Output filtering or warning suppression by pattern matching is not acceptable.

Native package managers, operating-system security updates, and vendor-managed desktop applications retain their explicit ownership boundaries until their own reconciliation lanes are defined.

## Consequences

- rolling tools can be adopted daily without waiting for a sprint,
- all machines converge on the same accepted rolling versions,
- normal version bumps need no repeated human decision,
- failed updates are isolated before adopted state changes,
- `mise.global.lock` becomes generated operational state committed to the repository,
- the update workflow receives narrowly scoped write/merge authority.

## Re-evaluation triggers

Reconsider this decision if mise changes global lockfile or locked-install semantics, update latency requires an event-driven trigger, supported platforms cannot be verified reliably, or repository rules cannot safely express the generated-state exception.
