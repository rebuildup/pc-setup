# ADR-0014: Orca は macOS の任意の worktree frontend とし、設定と Skill stub は Orca 自身が持つ

- Status: Accepted
- Date: 2026-10-17
- Related: ADR-0006

## Context

macOS には Orca（stablyai/orca）を `mise.global.toml` の `brew-cask:stablyai/orca/orca` で導入している。Orca は、並列に動かすエージェントの worktree、terminal、diff review、モバイル通知を一つの画面にまとめるデスクトップアプリである。

開発の正しさは rebuildup/project-init の方針に従う。worktree の作成・削除時の処理は、各 project の `mise run worktree:setup` / `worktree:teardown` が持つ。Worktrunk と Orca はどちらも、それを呼ぶだけの frontend である。

Orca には、pc-setup が宣言的に管理しにくい性質がある。

- 設定は Orca 自身の userData 内にある profile state（database と data file、backup、migration を含む）に保存される。設定を変更する CLI はない。
- Orca は自分の Agent Skill stub（`orca-cli` 等）を `--global` に入れ、updater が実行中の build の commit に固定して入れ直す。
- Homebrew cask は macOS だけである。Windows は GitHub Releases の installer、Linux は AppImage / deb / rpm で配布されている。

## Decision

### 位置づけ

Orca は macOS の任意の GUI frontend とする。開発の進め方を Orca に依存させない。Orca がなくても、Worktrunk か plain git で同じ worktree の状態を作れる。

### 導入

macOS では、引き続き Homebrew cask を `mise bootstrap packages apply` で導入する。cask は stable channel を追う。

### pc-setup が持たないもの

- **Orca の設定**：Orca の profile state を、ファイルの配置や書き換えで管理しない。Orca が自分の migration と backup で扱う状態であり、外から書くと壊れるおそれがある。必要な設定は、手動の初回設定として README に書く。
- **Orca の Skill stub**：Orca の updater に任せる。stub は Orca の build と版を合わせる必要があるためである。project の `skills-lock.json` にも、dotfiles の共有 Skill にも入れない。

### 他 OS

Windows と Linux には、今は導入しない。実際にその環境で Orca を使うと決めた時に、導入経路（GitHub Releases の installer / AppImage 等）と更新の持ち主を決める。

## Consequences

- Orca を uninstall しても、どの project も移行作業なしで同じ workflow を続けられる。
- Orca の設定は machine ごとの手動手順になる。手順は `platforms/macos/README.md` に置く。
- Orca の Skill stub は、Orca の updater が global に置いたものだけが存在する状態になる。

## Re-evaluate

- Orca が、設定を宣言的なファイルや CLI で変更できるようになった場合
- Windows / Linux で Orca を日常的に使うことになった場合
- Orca の orchestration が experimental でなくなり、Supervisor として比較する場合
